# 🧺 Бот записи на стирку в общежитии

Telegram-бот на **pyTelegramBotAPI (telebot)** + **MySQL**. Жильцы регистрируются (фамилия + комната),
видят расписание недели, записываются на стирку и отменяют записи. Старосты управляют своим этажом,
администратор — всем ботом.

## Возможности

**Жилец**
- регистрация: фамилия и номер комнаты (3 цифры: первая — этаж, две следующие — комната; можно с буквой — `323а`, это отдельная комната того же этажа); этаж и крыло определяются автоматически;
- расписание недели **картинкой**: 🟢 свободно, 🔴 занято (своя запись подписана «ВЫ»), ⚪ нельзя записаться (прошло или закрыто); под ней — день недели и дата, выбор **сначала дня, потом времени**;
- «Мои записи» и отмена своей записи до начала стирки;
- смена фамилии или комнаты — **только заявкой**: она уходит старосте этажа и вступает в силу после его подтверждения;
- кнопка «✉️ Написать администратору» — администратор отвечает прямо в боте;
- заявка на роль старосты — в профиле (подтверждает администратор).

**Староста** (только свой этаж)
- записывается сам, как обычный жилец;
- видит, кто записан, и отменяет чужие записи (жилец получает уведомление);
- закрывает запись: на весь день, на период дат (`14.10-20.10`) или на часть дня («с 17:00 по 21:15»); попавшие записи отменяются с уведомлением; закрытие можно снять;
- исключает комнату или отдельного жильца (кто не скинулся за стирку) и возвращает их;
- принимает или отклоняет заявки жильцов на смену фамилии/комнаты (уведомление приходит сразу с кнопками; при переезде на другой этаж заявку видят старосты обоих этажей, а если старосты нет — администратор);
- список жильцов этажа.

**Администратор** (по `telegram_id` из `.env`)
- аккаунт создаётся автоматически при запуске;
- подтверждает/отклоняет заявки старост (кнопки приходят прямо в личку), снимает старост;
- получает сообщения от жильцов и отвечает им кнопкой «↩️ Ответить»;
- видит все заявки на изменение данных;
- открывает панель любого этажа и делает всё, что староста;
- статистика и выгрузка лог-файлов прямо в Telegram.
- без звука получает уведомление о каждом новом пользователе (старосты — о новых жильцах своего этажа).

## Правила расписания

| | Этажи 2–4 | 5 этаж |
|---|---|---|
| Дни стирки | вт – вс (пн — выходной) | пн – сб; **1 крыло** (511–527): вт, чт, сб; **2 крыло** (501–510, 528–536): пн, ср, пт |
| Время | 06:30–07:15, 08:15–09:00, 10:00–10:45, 11:45–12:30, 13:30–14:15, 15:15–16:00, 17:00–17:45, 18:45–19:30, 20:30–21:15, 22:15–23:00 | 06:30–07:24, 08:30–09:24, 10:30–11:24, 12:30–13:24, 14:30–15:24, 16:30–17:24, 18:30–19:24, 20:30–21:24, 22:00–22:54 |
| Лимит | человек — не больше 2 записей в день | комната — не больше 1 стирки в день |
| Открытие записи на новую неделю | понедельник 15:00 | воскресенье 15:00 |

1 этаж в записи не участвует. Сетки времени задаются в `laundry/schedule.py` (`REGULAR_SLOTS`, `FLOOR5_SLOTS`),
время открытия недели — в `.env`.

## Установка (Ubuntu / Debian)

```bash
sudo apt update
sudo apt install -y python3 python3-venv mysql-server
```

### 1. База данных

```bash
sudo mysql
```
```sql
CREATE DATABASE laundry_bot CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'laundry_bot'@'localhost' IDENTIFIED BY 'надёжный_пароль';
GRANT ALL PRIVILEGES ON laundry_bot.* TO 'laundry_bot'@'localhost';
FLUSH PRIVILEGES;
```
Таблицы бот создаёт сам при запуске (схема — в `schema.sql`, её можно выполнить и вручную).

### 2. Проект

```bash
sudo useradd -r -m -d /opt/laundry_bot laundry          # отдельный пользователь для сервиса
sudo cp -r . /opt/laundry_bot && sudo chown -R laundry:laundry /opt/laundry_bot
cd /opt/laundry_bot
sudo -u laundry python3 -m venv venv
sudo -u laundry venv/bin/pip install -r requirements.txt
```

### 3. Настройка `.env`

Откройте `.env` и заполните:
- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather);
- `ADMIN_IDS` — ваш telegram_id (узнать: [@userinfobot](https://t.me/userinfobot)); несколько — через запятую;
- `DB_USER`, `DB_PASSWORD`, `DB_NAME` — из шага 1;
- `MAX_FLOOR`, `MAX_ROOM_ON_FLOOR` — сколько этажей и комнат на этаже (для проверки номера комнаты).
- `FLOOR_MAX_ROOMS` — этажи со своим максимумом номера (по умолчанию `3:35`: на 3 этаже вместо 336 есть 323а);
- `LETTER_ROOMS` — существующие комнаты с буквой (по умолчанию `323а`);
- `PROXY_URL` — SOCKS5-прокси для Telegram, например `socks5h://user:password@host:1080` (пусто — напрямую).

### 4. Запуск

Проверка вручную:
```bash
sudo -u laundry venv/bin/python main.py
```
Как сервис (автозапуск и перезапуск при сбое):
```bash
sudo cp laundry-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now laundry-bot
sudo systemctl status laundry-bot
```

На Windows для разработки: `python -m venv venv`, `venv\Scripts\pip install -r requirements.txt`, `venv\Scripts\python main.py`.

## Логи

Папка `logs/` (путь меняется в `LOG_DIR`), файлы ротируются по `LOG_MAX_MB` МБ, хранится `LOG_BACKUP_COUNT` копий:

| Файл | Что внутри |
|---|---|
| `bot.log` | всё: запуск, входящие действия (на уровне DEBUG), предупреждения |
| `errors.log` | только ошибки с полным трейсбеком |
| `actions.log` | журнал действий: регистрации, записи, отмены, закрытия, баны, решения по старостам |

Дополнительно лог пишется в stdout → `journalctl -u laundry-bot -f`. Администратор может скачать
логи кнопкой «📄 Логи» в админ-панели.

## Как устроено

- **Защита от двойной записи.** Уникальный индекс `(floor, slot_date, slot_start, active_flag)`
  не даёт занять одно время дважды, даже если двое нажали кнопку одновременно; отменённые записи
  остаются в истории. Лимиты «2 в день» и «комната 1 раз в день» проверяются в той же транзакции
  с блокировкой строк жильцов комнаты.
- **Время.** Все расчёты — в часовом поясе `TIMEZONE` (по умолчанию Europe/Samara).
- **Расписание-картинка** генерируется заново при каждом открытии или нажатии «🔄 Обновить»; при переходе к дню и обратно бот меняет подпись и само изображение в том же сообщении, не засоряя чат.
- **Одна машинка на этаж**: одна ячейка таблицы — одна запись. Крылья 5 этажа делят одну машинку по дням.
- Незаконченные шаги диалога (например, ввод фамилии) хранятся в памяти: после перезапуска бота
  их нужно начать заново, все данные в БД сохраняются.
