# 🧺 Бот записи на стирку в общежитии

Два бота с одной базой **MySQL**: **Telegram** (pyTelegramBotAPI) и **ВКонтакте** (сообщество, `vk_api`).
Жильцы регистрируются (фамилия + комната), видят расписание недели, записываются на стирку и отменяют
записи. Старосты управляют своим этажом, администратор — всем ботом.

Машинка одна, поэтому всё общее: запись, сделанная в VK, видна в Telegram и наоборот; староста из одного
мессенджера отменяет запись жильца из другого — и тот получает уведомление у себя. Боты — два отдельных
процесса (`main.py` и `vk_main.py`), можно запускать любой из них или оба.

## Возможности

Возможности в обоих мессенджерах одинаковые; отличия VK собраны в разделе [«Бот ВКонтакте»](#бот-вконтакте).

**Жилец**
- регистрация: фамилия и номер комнаты (3 цифры: первая — этаж, две следующие — комната; можно с буквой — `323а`, это отдельная комната того же этажа); этаж и крыло определяются автоматически;
- расписание недели **картинкой**: 🟢 свободно, 🔴 занято (в ячейке — номер комнаты и фамилия, своя запись подписана «ВЫ»), ⚪ нельзя записаться (прошло или закрыто); запись, время которой прошло, становится серой, но комната и фамилия на ней остаются; под картинкой — день недели и дата, выбор **сначала дня, потом времени**;
- «Мои записи» и отмена своей записи до начала стирки;
- смена фамилии или комнаты — **только заявкой**: она уходит старосте этажа и вступает в силу после его подтверждения;
- кнопка «✉️ Написать администратору» — администратор отвечает прямо в боте;
- заявка на роль старосты — в профиле (подтверждает администратор);
- **привязка второго мессенджера** — в профиле кнопка «🔗 Привязать ВКонтакте» / «🔗 Привязать Telegram»:
  бот выдаёт код на 15 минут, его нужно отправить другому боту. После этого человек — один пользователь
  в базе: общие записи, лимит «2 в день», роль и исключения; уведомления приходят в оба мессенджера.

**Староста** (только свой этаж)
- записывается сам, как обычный жилец;
- видит, кто записан, и отменяет чужие записи (жилец получает уведомление);
- закрывает запись: на весь день, на период дат (`14.10-20.10`) или на часть дня («с 17:00 по 21:15»); попавшие записи отменяются с уведомлением; закрытие можно снять;
- исключает комнату или отдельного жильца (кто не скинулся за стирку) и возвращает их;
- принимает или отклоняет заявки жильцов на смену фамилии/комнаты (уведомление приходит сразу с кнопками; при переезде на другой этаж заявку видят старосты обоих этажей, а если старосты нет — администратор);
- список жильцов этажа.

**Администратор** (по `ADMIN_IDS` — id в Telegram и `VK_ADMIN_IDS` — id в VK из `.env`)
- аккаунт создаётся автоматически при запуске;
- подтверждает/отклоняет заявки старост (кнопки приходят прямо в личку), снимает старост;
- получает сообщения от жильцов и отвечает им кнопкой «↩️ Ответить»;
- видит все заявки на изменение данных;
- открывает панель любого этажа и делает всё, что староста;
- статистика и выгрузка лог-файлов прямо в мессенджер;
- в Telegram без звука получает уведомление о каждом новом пользователе (старосты — о новых жильцах
  своего этажа). В VK тихих сообщений нет, поэтому туда это уведомление не отправляется.

## Правила расписания

| | Этажи 2–4 | 5 этаж |
|---|---|---|
| Дни стирки | вт – вс (пн — выходной) | пн – сб; **1 крыло** (511–527): вт, чт, сб; **2 крыло** (501–510, 528–536): пн, ср, пт |
| Время | 06:30–07:15, 08:15–09:00, 10:00–10:45, 11:45–12:30, 13:30–14:15, 15:15–16:00, 17:00–17:45, 18:45–19:30, 20:30–21:15, 22:15–23:00 | 06:30–07:24, 08:30–09:24, 10:30–11:24, 12:30–13:24, 14:30–15:24, 16:30–17:24, 18:30–19:24, 20:30–21:24, 22:00–22:54 |
| Лимит | человек — не больше 2 записей в день | комната — не больше 1 стирки в день |
| Открытие записи на новую неделю | понедельник 15:00 | воскресенье 15:00 |

1 этаж в записи не участвует. Сетки времени задаются в `laundry/schedule.py` (`REGULAR_SLOTS`, `FLOOR5_SLOTS`),
время открытия недели — в `.env`.

## Установка (Ubuntu / Debian)

```bash
sudo apt update
sudo apt install -y python3 python3-venv mysql-server
```

### 1. База данных

```bash
sudo mysql
```
```sql
CREATE DATABASE laundry_bot CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'laundry_bot'@'localhost' IDENTIFIED BY 'надёжный_пароль';
GRANT ALL PRIVILEGES ON laundry_bot.* TO 'laundry_bot'@'localhost';
FLUSH PRIVILEGES;
```
Таблицы бот создаёт сам при запуске (схема — в `schema.sql`, её можно выполнить и вручную).

### 2. Проект

```bash
sudo useradd -r -m -d /opt/laundry_bot laundry          # отдельный пользователь для сервиса
sudo cp -r . /opt/laundry_bot && sudo chown -R laundry:laundry /opt/laundry_bot
cd /opt/laundry_bot
sudo -u laundry python3 -m venv venv
sudo -u laundry venv/bin/pip install -r requirements.txt
```

### 3. Настройка `.env`

Файл `.env` один на оба бота (образец — `.env.example`). Откройте `.env` и заполните:
- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather);
- `ADMIN_IDS` — ваш telegram_id (узнать: [@userinfobot](https://t.me/userinfobot)); несколько — через запятую;
- `VK_TOKEN`, `VK_GROUP_ID`, `VK_ADMIN_IDS` — для бота ВКонтакте, см. раздел [«Бот ВКонтакте»](#бот-вконтакте);
- `DB_USER`, `DB_PASSWORD`, `DB_NAME` — из шага 1;
- `MAX_FLOOR`, `MAX_ROOM_ON_FLOOR` — сколько этажей и комнат на этаже (для проверки номера комнаты).
- `FLOOR_MAX_ROOMS` — этажи со своим максимумом номера (по умолчанию `3:35`: на 3 этаже вместо 336 есть 323а);
- `LETTER_ROOMS` — существующие комнаты с буквой (по умолчанию `323а`);
- `PROXY_URL` — SOCKS5-прокси для Telegram, например `socks5h://user:password@host:1080` (пусто — напрямую).

### 4. Запуск

Проверка вручную:
```bash
sudo -u laundry venv/bin/python main.py
```
Как сервис (автозапуск и перезапуск при сбое):
```bash
sudo cp laundry-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now laundry-bot
sudo systemctl status laundry-bot
```

На Windows для разработки: `python -m venv venv`, `venv\Scripts\pip install -r requirements.txt`, `venv\Scripts\python main.py`.

## Бот ВКонтакте

VK-бот — отдельный процесс (`vk_main.py`) рядом с Telegram-ботом. База и файл `.env` у них общие;
таблицы под VK (`users.vk_id` и др.) бот добавляет сам при первом запуске, существующие данные не меняются.

### 1. Настройка сообщества

1. Создайте сообщество (или откройте существующее): [vk.com/groups](https://vk.com/groups) → «Создать сообщество».
2. **Управление → Сообщения**: включите «Сообщения сообщества».
3. **Управление → Сообщения → Настройки для бота**: включите «Возможности ботов» и «Добавить кнопку „Начать“».
4. **Управление → Дополнительно → Работа с API → Ключи доступа → Создать ключ**. Отметьте права:
   **сообщения сообщества**, **фотографии** (картинка расписания), **документы** (выгрузка логов администратору).
   Скопируйте ключ — это `VK_TOKEN`. Никому его не показывайте.
5. Там же, вкладка **Long Poll API**: «Long Poll API» — **Включено**, «Версия API» — **5.199**.
   Во вкладке «Типы событий» отметьте: **Входящее сообщение** (`message_new`),
   **Действие с сообщением** (`message_event` — нажатия кнопок), **Разрешение на получение** (`message_allow`),
   **Запрет на получение** (`message_deny`).
6. Узнайте id сообщества — число на странице «Работа с API» или в адресе `vk.com/club<число>`. Это `VK_GROUP_ID`.

### 2. Настройка `.env`

Добавьте в `.env` (тот же файл, что у Telegram-бота):

```
VK_TOKEN=vk1.a.…          # ключ доступа сообщества из шага 4
VK_GROUP_ID=123456789     # id сообщества, только число
VK_ADMIN_IDS=11111,22222  # id администраторов в VK через запятую, только числа
```

Свой id в VK можно узнать у самого бота: запустите его и напишите слово **id**. После изменения `.env`
перезапустите **оба** бота — список администраторов читают оба.

Если `VK_TOKEN` пуст, Telegram-бот работает как раньше, а уведомления в VK пропускаются (и наоборот —
VK-бот без `BOT_TOKEN`). `PROXY_URL` относится только к Telegram, VK-бот ходит напрямую.

### 3. Запуск

В VS Code на Windows (в терминале PowerShell, из папки проекта):
```powershell
venv\Scripts\pip install -r requirements.txt   # один раз: появилась зависимость vk_api
venv\Scripts\python vk_main.py
```
Telegram-бот запускается во втором терминале: `venv\Scripts\python main.py`.

На сервере — вторым сервисом рядом с `laundry-bot`:
```bash
cd /opt/laundry_bot
sudo -u laundry venv/bin/pip install -r requirements.txt
sudo cp laundry-vk-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now laundry-vk-bot
sudo systemctl restart laundry-bot            # Telegram-боту тоже нужен новый код и .env
sudo systemctl status laundry-vk-bot
```

### Что важно знать про VK

- **Сообщество может писать только тем, кто сам ему написал** (или разрешил сообщения). Поэтому
  **администраторам и старостам нужно один раз написать боту** (нажать «Начать») — иначе заявки и
  уведомления до них не дойдут; в логе при этом будет предупреждение «ошибка 901». Жильцы пишут боту
  при регистрации, так что им ничего дополнительно делать не нужно.
- **Тихих сообщений в VK нет.** Уведомление о новом жильце в Telegram приходит без звука, а в VK не
  отправляется вовсе; новых жильцов видно в «👥 Жильцы этажа» и в статистике.
- **Команды** вместо `/start`, `/cancel`: слова «начать», «меню», «отмена», «помощь», «id» (и `/start` тоже).
- **Клавиатуры.** В сообщении VK помещается не больше 10 кнопок в 6 рядах, поэтому длинные списки
  (время стирки, записи дня, заявки) листаются кнопками «◀ / ▶», а длинные подписи сокращаются.
- **Оформление.** В VK нет жирного и моноширинного текста — те же сообщения приходят обычным текстом.
  Пользователи VK в списках и заявках показаны упоминанием (`[id123|Иванов]`), на которое можно нажать.
- **Один человек в двух мессенджерах** без привязки считается двумя пользователями (лимит записей и
  исключение — у каждого аккаунта свои). Чтобы этого не было, жильцу достаточно один раз привязать второй
  мессенджер кодом из профиля. Привязка проходит, если второй аккаунт ещё не регистрировался либо записан
  в ту же комнату и не имеет предстоящих записей (иначе бот подскажет, что сделать). После пяти неверных
  кодов подряд ввод кодов с этого аккаунта закрывается на 15 минут.

## Логи

Папка `logs/` (путь меняется в `LOG_DIR`), файлы ротируются по `LOG_MAX_MB` МБ, хранится `LOG_BACKUP_COUNT` копий.
У каждого бота свои файлы — два процесса не пишут в один файл:

| Telegram-бот | VK-бот | Что внутри |
|---|---|---|
| `bot.log` | `vk_bot.log` | всё: запуск, входящие действия (на уровне DEBUG), предупреждения |
| `errors.log` | `vk_errors.log` | только ошибки с полным трейсбеком |
| `actions.log` | `vk_actions.log` | журнал действий: регистрации, записи, отмены, закрытия, баны, решения по старостам, привязки |

Дополнительно лог пишется в stdout → `journalctl -u laundry-bot -f` и `journalctl -u laundry-vk-bot -f`.
Администратор может скачать логи обоих ботов кнопкой «📄 Логи» в админ-панели (в VK для этого у ключа
доступа должно быть право «Документы»). Токены и пароли в логи не пишутся.

## Тесты

Тесты не требуют ни токенов, ни MySQL: VK API и Telegram Bot API заменены имитациями, база — SQLite во
временном файле, сеть заблокирована. Ваш `.env` и рабочая база не используются.

```powershell
venv\Scripts\python -m unittest discover -s tests -t . -v
```

Параметры `-s tests -t .` обязательны (без них запуск останавливается с подсказкой). Проверяются сценарии
обоих ботов и связка между ними: регистрация с ошибками ввода, запись (картинка → день → время →
подтверждение), лимиты, гонка за слот, 5 этаж и крылья, открытие недели, панель старосты, админ-панель,
привязка аккаунтов, лимиты клавиатур VK, поведение при ошибках API и обрыве Long Poll.

Миграцию базы и те же сценарии можно прогнать на настоящем MySQL/MariaDB — на сервере, где разрешено
создавать и удалять базы (тесты создают только базы `laundry_test_…` и удаляют их за собой):

```powershell
$env:TEST_MYSQL_HOST = "127.0.0.1"; $env:TEST_MYSQL_PORT = "3306"
$env:TEST_MYSQL_USER = "root"; $env:TEST_MYSQL_PASSWORD = "…"
venv\Scripts\python -m unittest discover -s tests -t . -v
```

Кнопки в обоих ботах несут одни и те же команды (`bk:d:20261007`, `m:3:x:15`, `chg:ok:7` …): в Telegram —
в `callback_data`, в VK — в `payload`. Поэтому кнопка из уведомления, отправленного одним ботом,
обрабатывается другим.

## Как устроено

- **Защита от двойной записи.** Уникальный индекс `(floor, slot_date, slot_start, active_flag)`
  не даёт занять одно время дважды, даже если двое нажали кнопку одновременно; отменённые записи
  остаются в истории. Лимиты «2 в день» и «комната 1 раз в день» проверяются в той же транзакции
  с блокировкой строк жильцов комнаты.
- **Время.** Все расчёты — в часовом поясе `TIMEZONE` (по умолчанию Europe/Samara).
- **Расписание-картинка** генерируется заново при каждом открытии или нажатии «🔄 Обновить»; при переходе к дню и обратно бот меняет подпись и само изображение в том же сообщении, не засоряя чат.
- **Одна машинка на этаж**: одна ячейка таблицы — одна запись. Крылья 5 этажа делят одну машинку по дням.
- Незаконченные шаги диалога (например, ввод фамилии) хранятся в памяти: после перезапуска бота
  их нужно начать заново, все данные в БД сохраняются.
- **Два бота — одна логика.** Правила расписания, лимиты, баны, закрытия и заявки реализованы один раз
  (`services.py`, `schedule.py`, `db.py`); обработчики Telegram и VK только показывают экраны.
  Пользователь в базе — одна строка `users` с `telegram_id`, `vk_id` или обоими (после привязки).
- **Уведомления между мессенджерами** отправляет `notify.py`: Telegram-процесс пишет жильцам VK через
  VK API по ключу сообщества, VK-процесс пишет в Telegram через Bot API (без polling).
